# House Money v2: what changed and how it works

Source of truth is the Solidity in `contracts/src` (read the NatSpec). This file is the map.

Tooling in this sandbox: forge at `$HOME/.foundry/bin` (add to PATH); ALWAYS pass `--offline` (no compiler
downloads; solc 0.8.28 installed). `foundry.toml` now has `via_ir = true` (the engine only fits under 24 KB that
way). Typed ABIs for JS are generated by `node scripts/export-abis.mjs` into `keeper/src/abi.ts` and
`frontend/src/lib/abi.ts` (exports `perpEngineAbi`, `engineLensAbi`, `houseVaultAbi`, `rewardTokenAbi`,
`publisherOracleAbi`, `testUSDCAbi`). Compiled artifacts (abi + bytecode) are in `contracts/out/<Name>.sol/<Name>.json`.
The shell cannot reach any chain RPC, Hermes, exchanges or other internet hosts except the npm registry and GitHub.

## Contracts

| Contract | Role |
| --- | --- |
| `PerpEngine` | margin custody, positions, orders, liquidation, settlement of dated markets |
| `EngineLens` | all aggregated reads (positions, orders, markets with prices). Engine has only primitive getters |
| `PythOracle` | stateless adapter: Pyth-shaped feed(s) -> validated 18-dec bid/mid/ask; crosses and inversion |
| `HouseVault` | ERC-4626 vault (hmUSDC), counterparty; mark-to-market aware pricing; epoch staker yield |
| `RewardToken` | HOUSE: 100 per USDC lost; staking with streamed USDC yield |
| `testnet/PublisherOracle` | Pyth-compatible pull oracle fed by publisher-signed updates (testnet only) |
| `testnet/TestUSDC` | open-mint 6-dec collateral for testnets (`mint(to, amount)`, max 1,000,000e6 per call) |
| `Types.sol` | file-level structs/enums: `Position, Market, MarketConfig, Order, OrderType, OpenParams, LimitParams, PositionView, OraclePrice, PriceStatus` |

Constructors:
- `PythOracle(IPyth pyth)`; pass the real Pyth address, or a `PublisherOracle` address on testnet
- `HouseVault(IERC20 usdc, address engine, address rewardToken, uint256 withdrawLockPeriod, uint256 epochLength)`
- `RewardToken(address vault, address engine, uint256 streamPeriod)`
- `PerpEngine(IERC20 usdc, PythOracle oracle, IHouseVault vault, IRewardToken rewardToken, address owner)`
- `EngineLens(PerpEngine engine)`
- `PublisherOracle(address owner, address publisher)`
Vault, token and engine reference each other immutably, so their addresses are predicted from the deployer nonce
(deploy order: oracle first; then vault(n), token(n+1), engine(n+2); lens after).

## Instruments (new)

A market = `MarketConfig{symbol, feedId, quoteFeedId, invert, maxLeverage, expiry, maxOiPerSide, skewScale}` listed
with `engine.addMarket(bytes32 marketId, MarketConfig)`.
- plain perp: `marketId == feedId` by convention, `quoteFeedId = 0`, `expiry = 0`
- cross: `quoteFeedId != 0`, price = feed / quoteFeed (e.g. ETH/BTC); `marketId = keccak256(symbol)`
- inverted: `invert = true` (JPY/USD from USD/JPY)
- dated future: `expiry != 0`. No opens at/after expiry (`MarketExpired`). After expiry anyone calls
  `settleMarket(marketId, priceUpdate)` once (price must be published at/after expiry) which fixes
  `settlementPrice`; from then the market's price is the settlement price for ever; traders `closePosition`
  or anyone calls `settlePositions(bytes32[] keys)` to close them (liquidating those past the threshold).
  Funding stops at expiry.
- All positions are sized in USDC notional (`size`), so everything is fractional. "Contracts" in a UI are
  `size / price` units of the underlying.
- In structs/events the market id field is still called `priceId`.

## Trading changes

- `OrderType { LimitOpen=0, TakeProfit=1, StopLoss=2, Close=3 }`.
- `setTriggerOrder(marketId, orderType, triggerPrice)` now also accepts `Close`: a keeper-executed market close;
  `triggerPrice` = worst acceptable price (min for longs, max for shorts), `0` = no bound. Escrows `executionFee`
  on creation; calling again moves it for free. Position gained `closeOrderId`.
- A marketable `createLimitOrder` (trigger at/through the current price, e.g. ask*(1+slippage) for a long) is the
  keeper-executed market open. This is the path for people using wallets: no price update, no staleness race.
  `openPosition` / `closePosition` (direct, price must be <= `maxPriceAge` old) remain for bots.
- Closing (direct or by order) requires a price published in a later second than the open (`PriceNotAfterOpen`).
- Limit fills re-validate margin/leverage/market status, and do not fill while price is beyond the order's own
  stop (`InvalidTrigger`).
- Profit per position capped at `maxProfitMultiple` (default 10) x margin.
- Payments to traders never revert: on a refused transfer (blocklisted) the amount goes to `claimable[trader]`,
  collected by that same address with `claim()`. Engine custody = margins + order escrows + `totalClaimable`.
- `vault.payoutTraderProfit` now pays the engine, which forwards to the trader in one payment.
- `engine.markets(id)` public getter is gone: use `engine.getMarket(id)` (returns `Market` struct) or
  `lens.getMarkets()` -> `MarketView{id, market, fundingRate, hasPrice, price}`.
- Moved to the lens: `getPositions(offset,limit)`, `getTraderPositions(trader)`, `getPositionState(key, price)`,
  `getOrders(offset,limit)`, `getTraderOrders(trader)`. Engine keeps `getPosition`, `getPositionByKey`,
  `positionKeys(offset,limit)`, `positionCount`, `getOrder`, `orderIds(offset,limit)`, `orderCount`,
  `quoteOpenFee`, `fundingRate`, `currentFundingIndex`, `getPrice`, `getMarketIds`, `getMarket`.
- `liquidate(address)`, `liquidate(address, bytes[])`, `liquidateBatch(bytes32[], bytes[])` unchanged.
- New engine views for the vault: `unrealizedTraderPnl()` (signed, last known prices, any age),
  `reservedLiquidity()` now reserves on NET skew per market (sum |long - short| / multiple), not gross OI.
- New admin: `setMaxProfitMultiple(1..100)`. `MAX_MARKETS = 64`.
- Oracle is reached through `PythOracle.peek(feedId, quoteFeedId, invert, maxAge, maxConfBps)`.

## Vault and staking changes

- No more 85/15 split on inflows. `receiveTraderLoss` / `receiveFees` add 100% to `totalHouseBalance`.
  Events are now `TraderLossReceived(trader, amount)` and `FeesReceived(amount)`.
- Valuation: `markedValue()` = realised balance - unrealised trader PnL (floored at 0);
  `exitValue()` = min(realised, marked); `entryValue()` = max(realised, marked); `totalAssets()` = `exitValue()`.
  Deposits/mints are priced at entry value, withdrawals/redeems at exit value. With no open positions all three
  are equal and behaviour is plain ERC-4626.
- Staker yield: `settleEpoch()` (anyone, once per `epochLength`): if exit value per share > `highWaterMark`,
  15% of that gain moves from `totalHouseBalance` to `pendingStakerYield` and is sent to `rewardToken.notifyYield`.
  With nobody staked the mark still rises and the house keeps everything. Reverts `EpochNotOver(next)` if early.
- RewardToken streams each notified amount linearly over `streamPeriod` (leftover of a running stream is merged;
  yield that streams while nobody is staked is rolled into the next stream). `earned(account)` grows over time.
  `NoStakers` error removed. New views: `yieldRate`, `periodFinish`, `lastUpdateTime`, `streamPeriod`.

## Oracle on Arc Testnet (important)

Pyth's Hermes requires a paid API key since 2026-08-26 and nobody pushes Pyth prices on Arc Testnet, so the
testnet deployment uses `PublisherOracle` in place of the Pyth contract. Same call surface the engine uses:
`getPriceUnsafe(bytes32)`, `getUpdateFee(bytes[])` (returns 0), `updatePriceFeeds(bytes[]) payable`.
An update is `abi.encode(bytes32 id, int64 price, uint64 conf, int32 expo, uint64 publishTime, bytes sig)`,
`sig` = publisher's EIP-191 `personal_sign` over
`keccak256(abi.encode(uint256 chainId, address oracle, bytes32 id, int64 price, uint64 conf, int32 expo, uint64 publishTime))`
(viem: `account.signMessage({ message: { raw: digest } })`; or read `oracle.updateDigest(...)`).
Only strictly newer `publishTime` replaces a stored price; `publishTime > block.timestamp + 2` reverts.
Feed ids are the Pyth ids, so moving to real Pyth later is configuration only.

Price source for the publisher: Kraken public REST (CORS-enabled, no key):
`https://api.kraken.com/0/public/Ticker?pair=XBTUSD,ETHUSD,SOLUSD,EURUSD,USDJPY,PAXGUSD` -> `result[<key>].a[0]` ask,
`.b[0]` bid, `.c[0]` last. Result keys are Kraken's own names (`XXBTZUSD`, `XETHZUSD`, `SOLUSD`, `ZEURZUSD`, `ZUSDZJPY`,
`PAXGUSD`), so match by trying both forms. Candles: `https://api.kraken.com/0/public/OHLC?pair=XBTUSD&interval=1`
(`interval` minutes: 1,5,15,60,240,1440) -> `result[<key>]` = `[time, open, high, low, close, vwap, volume, count][]`.
Mid = (bid+ask)/2, conf = max(half spread, 1 bp of mid).
